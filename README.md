### Самое неочевидное решение в TODO 3    

Самым неочевидным оказалось, на что делить логиты перед softmax. Кажется логичным делить на $d_k$, ведь мы хотим их уменьшить. Но правильно делить на $\sqrt{d_k}$.

Скалярное произведение $q \cdot k$ — это сумма $d_k$ чисел, и чем больше $d_k$, тем сильнее разбросаны логиты (разброс растёт примерно как $\sqrt{d_k}$). Деление на корень возвращает разброс к нормальному уровню около единицы при любой размерности головы.

Если делить на $d_k$, логиты сожмутся слишком сильно, и внимание станет почти равномерным: модель перестанет различать позиции. Если не делить вообще, при больших $d_k$ логиты станут огромными, softmax «залипнет» в почти one-hot распределение, и градиенты через него перестанут течь, так что модель не будет учиться.

Главная сложность в том, что эта ошибка не ломает ни формы тензоров, ни сумму весов, ни причинную маску. Код запускается и выглядит рабочим, просто модель учится хуже. Заметить её можно только сверкой с эталоном или отдельной проверкой масштаба логитов.

### Выполнение  

В ходе выполнения были локализированы, описаны и исправлены 3 ошибки.

| # | Функция и строка | Механизм поломки | Как исправили |
|---|---|---|---|
| 1 |Где: sinusoidal_positional_encoding, строка position = torch.arange(1, length + 1, dtype=torch.float32).unsqueeze(1).|Позиции нумеруются с 1 (arange(1, L+1)) вместо 0 (arange(0, L)), поэтому всё кодирование сдвинуто на шаг: первый токен получает кодирование позиции 1, а последняя позиция L выходит за допустимый диапазон 0..L−1. Позиционное кодирование — вектор, прибавляемый к эмбеддингу, чтобы модель знала место токена; формула задаёт его для pos = 0..L−1, так что сдвиг делает все строки несовпадающими с формулой и даёт модели неверную информацию о порядке.|position = torch.arange(length, dtype=torch.float32).unsqueeze(1)  |
| 2 |Где: LayerNorm.forward, строки: mean = x.mean(dim=0, keepdim=True),var  = x.var(dim=0, keepdim=True, unbiased=False).|LayerNorm нормирует каждый токен отдельно: вычитает среднее и делит на стандартное отклонение по его признакам (d_model), чтобы значения внутри токена имели нулевое среднее и единичную дисперсию — это стабилизирует обучение. В коде среднее и дисперсия считаются по dim=0 — оси батча, то есть усредняются значения одного и того же канала у всех примеров батча, а не признаки внутри одного токена. В результате каждый токен не центрируется по своим признакам, а нормировка одного примера зависит от остальных: изменился другой пример в батче — изменился и выход этого. Модель получает нестабильные, «протекающие» между примерами значения вместо независимо нормированных токенов.|mean = x.mean(dim=-1, keepdim=True), var = x.var(dim=-1, keepdim=True, unbiased=False).  |
| 3 |Где: scaled_dot_product_attention, weights = torch.softmax(scores, dim=-2).|Матрица логитов имеет форму (B, H, L_q, L_k), где по строкам — запросы, по столбцам — ключи. Внимание — это набор весов, с которыми каждый запрос смотрит на все ключи; чтобы эти веса были вероятностями, softmax (он превращает набор чисел в вероятности с суммой единица) должен применяться по строке, то есть по ключам (dim=-1). В коде стоит dim=-2: нормируются столбцы — для каждого ключа распределение по запросам. Тогда каждая строка уже не суммируется в единицу, и взвешенная сумма value смешивает несогласованные веса, выход внимания перестаёт быть «средним по разрешённым ключам», а из-за неправильной нормировки позиция получает вклад от будущих токенов (модель подглядывает в будущее).|weights = torch.softmax(scores, dim=-1)|
